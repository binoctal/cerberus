# HTTP Route Case Generator v2 — Design

Date: 2026-08-26
Status: approved (approach A, compound status class; pending user spec review)
Predecessor: reachability sweep (`internal/head/scout/http_route_cases.go`, c358963 + 1cd4a4f)

## Problem

v1 gives every mounted route one bare-client reachability smoke
(`expect_status_class: any`). It proves the route answers, nothing more.
Four gaps, all confirmed as in-scope by the user:

1. No auth-shape assertions (unauthenticated requests should be rejected).
2. No request bodies (mutation handlers get an empty body).
3. Only the `admin` role gets JWT injection; other credentialed routes are
   probed bare.
4. `:param` segments use the placeholder `1`; handler semantics unverified.

## Non-negotiable constraint

SUT facts live in the vocabulary/protocol files, never in generator source
(same principle as `internal/project/violations_schema.go`). The generator
stays SUT-generic; all open-agents knowledge enters through reviewable,
diffable vocab facts produced by grounded extractors.

## 1. Data model (`internal/project/vocabulary.go`)

`VocabHTTPRoute` gains optional fields:

```yaml
http_routes:
  - method: GET
    path: /api/devices/:id
    middlewares: [authMiddleware]     # fact: every middleware before the handler
    auth: required                    # derived: middlewares ∩ service-level list
    min_body: {"name": "x"}           # minimal legal body from zod schema
    param_sources:                    # :id -> list-route chaining
      ":id": {route: "GET /api/devices", pick: "$[0].id"}
```

Service-level `http_auth_middlewares: [authMiddleware]` (one declaration per
service; default generated by heuristic `/auth|bearer|jwt/i` on observed
middleware names, hand-overridable). Middleware names are judgment; the
mount chain is fact — the two stay separate.

`auth` values:
- `required` — at least one middleware in the auth list
- `none` — zero middlewares
- `unknown` — middlewares present, none in the list

`ValidateVocabulary` extends: `auth` in enum; `min_body` (when present) must
be a JSON object; `param_sources` keys must name `:params` present in the
path, each `route` must resolve to a same-vocab route.

## 2. Extractors (extend `internal/vocabextract/extractor.mjs`)

ts-morph is already a dependency of the bundled Node extractor.

- **auth chain**: recognize both mount forms — prefix `app.use(path, mw)`
  and inline `router.get('/y', mw, handler)`. NOTE (review finding): the
  extractor currently handles NO `app.use` calls at all (only
  `app.route('/prefix', router)` mounting), and inline middleware args
  (`call.getArguments()[1..n-2]`, currently only arg0 is read) have never
  been inspected — both are new code, not extensions of existing traversal.
  Emit per-route `middlewares`.
- **body**: locate the handler's first `z.object({...})` argument; extract
  literal primitive fields only (string -> `"x"`, number -> `0`,
  boolean -> `false`). Anything else (`.refine`, non-literal, nested object,
  optional fields stay omitted) marks the body unextractable — omit
  `min_body` entirely. Prefer missing over guessing.
- **param chain**: for `/api/devices/:id`, find a GET route with the same
  prefix (`/api/devices`) in the same vocab and emit the default
  `param_sources` entry. `pick` defaults to `0.id`, hand-overridable in the
  vocab. Syntax note: dot-path, matching the existing `Capture` field
  semantics (`0.id`, `data.0.id`) — NOT JSON pointer.

## 3. Generator v2 (rewrite `internal/head/scout/http_route_cases.go`)

Every `auth: required` route emits two cases; others emit one:

| case | creds | assertion | bite |
|---|---|---|---|
| `<id>-unauth` | none | expect **4xx** | auth middleware removed -> 2xx -> red |
| `<id>-authed` | role JWT | GET + real `:param` -> **2xx**; mutation with `min_body` -> **2xx_4xx** | handler broken -> 5xx/404 -> red |
| reachability (v1) | none | any | fallback tier for `auth: none`/`unknown` |

Degradation rule: the `-authed` 2xx assertion requires either a param-free
path or a resolvable `param_sources` chain. A `:param` route with no
matching list route stays on the reachability tier (placeholder `1`,
`any`) — never assert 2xx against a guessed id.

Role injection generalizes the `adminRole` special case: routes match any
protocol role with a `CredentialRef` by path prefix (`/api/admin` -> admin,
everything else -> web), mapping declarable in the vocab.

New compound status class `2xx_4xx` added to `expect_status_class`
(extends the current `2xx|3xx|4xx|5xx|any` enum; decision (b) — coarse but
stable, matches the v1 honesty-tier philosophy: prove "no server error, no
routing error" first. An exact-code `expect_status` field ALREADY exists —
compound was chosen over exact codes for resilience to cross-route semantic
variation, not for lack of the capability).

Expectation text tiers update accordingly (authed+2xx wording differs from
reachability wording).

## 4. Executor support (`internal/head/agent`) — mostly already shipped

Review against the executor found the heavy lifting already present:

- `Body` field on `http_request` steps: exists (`types.go`).
- Response capture: exists — `Capture map[string]string` (dot-path ->
  per-case param), substitutable in later steps as `{{case.<name>}}`.
- Placeholder substitution covers `http_request` URL **and** Body via the
  shared `resolvePlaceholders`.

The only executor change: add `2xx_4xx` to `statusInClass` (and its error
message). List-route chaining is therefore purely a generator concern —
two steps inside one case: GET list (`capture`) then target route (assert),
no cross-case global state.

## 5. Compatibility

- Coverage denominator unchanged (all mounted routes, as v1).
- `partial`/`unsupported` marks stay preserved on re-extraction keyed by
  method|path — the merge path already exists and is tested
  (`TestRunProtocolVocabulary_ReextractPreservesAnnotations`); **the new
  fields (`middlewares`/`auth`/`min_body`/`param_sources`) must ride the
  same merge and that test must be extended to prove it**.
- Side effects: mutations with bodies write real rows to the dev database
  (cost already accepted in v1); real `:param` ids hit real handlers — same
  order of magnitude.
- Cases still ride WSCases for services with routes.

## 6. Testing & acceptance

1. Extractor unit tests: miniature Hono/zod testdata project (both mount
   forms, extractable/unextractable bodies, param-chain inference).
2. Real-source integration test (precedent:
   `ui_titles_openagents_integration_test.go`): sampled assertions on
   auth/body/param facts extracted from open-agents worker.ts.
3. `make check` + `make integration-openagents` green; coverage does not
   regress.
4. **Live break test** (the acceptance gate the user chose): temporarily
   comment out the authMiddleware mount in open-agents worker.ts — the
   `-unauth` cases must fail; restore — they must pass. This proves the
   assertions have teeth.

## Out of scope

- Exact status-code assertions (e.g. `expect_status: 401`).
- Auth assertions for `auth: unknown` routes (stay on reachability tier).
- Cross-leg observation reuse for `:param` values (UI-leg coupling).
- Runtime-learned expectations (rejected in brainstorm: would freeze bugs
  as expectations).
