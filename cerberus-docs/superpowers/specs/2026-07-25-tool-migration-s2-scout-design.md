# Tool-Migration S2 — Scout 双层 Tool-Calling — Design — 2026-07-25

## Background

S1 made the mock client tool-aware and locked provider tool-parse coverage, but
**no head calls `DecideWithTools`** — Scout still uses `Driver.Decide` (structured
JSON output) at every LLM call site. This is the root cause of GLM drift.

drift is not abstract — it is evidenced by code written to absorb it:

| drift point | expected shape | actual LLM output | absorption code |
|---|---|---|---|
| `tech_stack` | `["go","make"]` | `[{"language":"go","confidence":1.0}]` | `flexibleStrings`+`firstStringValue` (`types.go`) |
| `ws_relay` body | valid `relayIntent` JSON | role typo / missing step field / `<2` roles / unknown role | 6-layer validate + silent drop (`ws_relay.go`) |
| `PlanOutput` | closed `{"cases":[{8 fields}]}` JSON | missing field / unclosed JSON / bad nesting | `ParseStructuredOutput` fail → `fallbackPlan` |

Why drift happens: "emit JSON matching this schema" is a **soft constraint**
(described in prompt text); larger JSON drifts more, GLM especially. tool-calling
makes the schema a **hard constraint** (provider enforces tool-call input) and
breaks one large JSON into many small typed calls — drift becomes structurally
impossible.

## Goal

Migrate all four Scout `Decide` call sites to `DecideWithTools` via a **two-tier
tool surface**, delete every drift absorption patch, and remove the secondary
LLM round-trips that exist only to compensate for structured-output brittleness.

The four call sites:
1. `directPlan` / `runAIPlanning` → `PlanOutput{Cases[]}` (main plan path)
2. `Analyze` / `runAIInference` → `AnalyzeOutput{Endpoints,Pages,TechStack}`
3. `verifyServiceAttribution` → `ServiceAttributionCorrections` (post-hoc service fix)
4. `ToT` `propose`/`evaluate` → `ProposeOutput`/`EvaluateOutput` (deep plan, optional)

## Design

### 1. Two-tier tool surface (the core idea)

The current architecture is already mixed: most cases are high-level TestCases
with no `Steps` (executor rule-engine expands them), while `ws_relay`/`ws_cases`
produce TestCases **with `Steps`** (low-level choreography). The two-tier surface
lets the LLM pick the tier per case instead of forcing one.

| Tier | Tools | When the LLM uses it |
|---|---|---|
| **High-level intent** (one call = one TestCase, no Steps) | `test_http_endpoint`, `check_invariant`, `run_process`, `analyze_code`, `check_file`, `navigate`, `report_endpoint`, `report_page`, `declare_tech`, `propose_strategy` | Single-step semantic assertion (~90% of cases) |
| **Low-level step** (bare operation) | `ws_connect`, `ws_send`, `ws_receive`, `ws_disconnect` | Multi-step choreography (currently = WS; extensible) |
| **Grouping boundary** | `begin_case{name, expectation}` | Marks "the following step calls belong to one TestCase" |

Assembly rule:
- A high-level intent tool call → one TestCase with no `Steps`.
- `begin_case` followed by low-level step calls, up to the next `begin_case` /
  high-level tool / end-of-stream → one TestCase **with `Steps`** (the step calls
  in order).

This maps 1:1 onto the existing `TestCase{Steps?}` structure, so the executor
rule-engine and step runner need **zero changes**: no-Steps cases route as today,
Steps cases route through the existing step runner.

Minimal semantic overlap: low-level step tools exist **only for multi-step
choreography** (WS connect/send/recv coordination). http/file/process are
one-shot cases served by high-level tools — there is no `http_request` step tool
to collide with `test_http_endpoint`.

### 2. Call-site mapping

**directPlan** — LLM emits a stream of tool calls assembled into a TestPlan:

| Tool | Input fields | Produces |
|---|---|---|
| `test_http_endpoint` | `method, path, body?, service?, expect_status?, expect_body?` | http TestCase `{Method, Target:path, Body, Expectation, Service?}` |
| `check_invariant` | `invariant_id? \| (description, assertion?)` | invariant TestCase `{Expectation, Severity?}` |
| `run_process` | `action: build\|test\|lint\|exec, cmd?, expect?` | TestCase `{Action: process_build\|process_exec\|...}` |
| `analyze_code` | `action: lint\|symbols, target?` | TestCase `{Action: code_lint\|code_symbols}` |
| `check_file` | `action: exists\|read\|glob, path?, pattern?, expect?` | TestCase `{Action: file_exists\|file_read\|file_glob}` |
| `navigate` | `path, expect?` | TestCase `{Action: navigate, Target:path}` |
| `begin_case` | `name, expectation` | opens a Steps TestCase |
| `ws_connect` | `role, url?` | Step `{Action:ws_connect, ConnectionID:role, Role:role}` |
| `ws_send` | `role, message` | Step `{Action:ws_send, ConnectionID:role, Message}` |
| `ws_receive` | `role, type?, aliases?, timeout?, assert?` | Step `{Action:ws_receive, ConnectionID:role, Type, Asserts, Timeout}` |
| `ws_disconnect` | `role` | Step `{Action:ws_disconnect, ConnectionID:role}` |

- `TestCase.ID` is **generated by code** (`tc-001` in emission order), never by
  the LLM — removes one drift vector.
- WS relay authoring: the LLM emits `begin_case` + a `ws_connect`/`ws_send`/
  `ws_receive` sequence directly. The `relayIntent` body-JSON disappears; the
  intent **is** the tool-call sequence.

**Analyze** — three high-level tools, one call per item, fully replacing
`AnalyzeOutput`:
- `report_endpoint{method, path, confidence?}`
- `report_page{path, confidence?}`
- `declare_tech{stack: [string]}`  ← kills `flexibleStrings` (schema enforces string array)

**verifyServiceAttribution — DELETED.** Service attribution moves into the
high-level tools' optional `service` field (the LLM knows the service list from
the prompt and tags correctly at production time). `attributeService` (path
prefix match) remains as the fallback when `service` is unset. This removes an
entire LLM round-trip that existed only to compensate for structured-output
brittleness.

**ToT** — split:
- `propose` → `propose_strategy{description, cases: [string]}` tool (multi-intent,
  benefits from tool-calling). Replaces `ProposeOutput`.
- `evaluate` → **deterministicized** (see §3). The `aiScore` LLM call and
  `evaluateDriver.Decide` are removed.

### 3. ToT evaluate deterministicization

Current scoring (`tot_evaluators.go:45`):
```
Score = (AIScore / 10 * 0.7) + (Coverage * 0.3)
```
`AIScore` (LLM, 70%) measures strategy quality (risk focus / completeness /
diversity / efficiency); `Coverage` (deterministic, 30%) is endpoint path
string-matching. Removing `AIScore` and leaving `Coverage` alone would collapse
the ranking to a 30% weak signal.

Replacement: a **multi-signal deterministic score** combining signals the code
can compute without an LLM, each normalized to [0,1]:

| Signal | Measures | Source |
|---|---|---|
| endpoint coverage | are known endpoints exercised | existing `coverageScore` |
| invariant coverage | are declared invariants addressed | case text vs `model.InvariantHints` |
| page coverage | are known pages exercised | case text vs `model.Navigation.Pages` |
| action diversity | happy + error + edge breadth | distinct action categories among cases |
| case-count adequacy | not under-specified | penalize very low case counts |
| goal keyword overlap | relevance to the stated goal | case text vs goal tokens |

`Score` = weighted sum of these signals (weights TBD in plan; endpoint coverage
and invariant coverage weighted highest). `AIScore`/`aiScore()`/`evaluateDriver`
removed.

**Trade-off (must be accepted):** deterministic signals are less nuanced than
LLM judgment — the beam-search ranking loses some quality discrimination. This
is acceptable because ToT is an optional mode (`deepPlan` defaults off) and the
win is a stable, reproducible, drift-free, zero-LLM-cost score. `reasoning` text
is lost; if retained for logging it becomes a deterministic per-signal breakdown.

### 4. Fallback policy — removed

Per the "no compatibility paths" decision: if `DecideWithTools` returns zero
tool calls or errors, Scout returns the error directly. No silent deterministic
fallback (`fallbackPlan` / config-only degradation). Problems surface instead of
being masked by low-quality generated cases.

### 5. augmentPlan aftermath

`augmentPlan` currently does three things; migration impact:
- `expandWSRelayCases` — **deleted**. Its "body-JSON → Steps" job vanishes (LLM
  authors Steps directly). Its validation logic (declared role / dup role /
  valid step) and `covered`-roles computation **move into the assembly layer**
  that converts the `begin_case`+ws_* sequence into a TestCase.
- `appendExecutorCases` — process/code cases are now authored by the LLM via
  high-level tools; the deterministic `GenerateExecutorCases` supplement is
  dropped. `WSCasesCovered` (protocol-derivable relay/connect cases the LLM may
  miss) is **retained** as a deterministic complement.
- `filterWSEndpointDrift` — **retained** as cheap insurance (the LLM now uses
  ws_* tools for WS endpoints, but the filter guards against residual drift).

### 6. Prompt changes

Each call site's prompt drops its `Output(...)` JSON-schema section and gains a
tool-definitions section (the tool names + input schemas above) plus guidance:
"use high-level tools for single-step cases; use `begin_case` + ws_* steps only
for multi-step connection choreography". Embedded prompt templates
(`internal/prompts` + `internal/head/scout` prompt constants) updated accordingly.

## Out of Scope

- Agent / Steer / Examiner heads (S3 / S4).
- Provider implementation (done in S1; S2 adds no provider code).
- `Driver.Decide` itself — other heads still use it; removing `Decide`
  project-wide is an S4 follow-up once all heads migrate.

## Testing

- **mock**: each tool gets a `SetToolResponse` preset test (high-level → one
  TestCase; `begin_case`+ws_* → one Steps TestCase). Assembly correctness
  (ID generation, service fallback, Steps ordering) covered by table tests.
- **provider tool-parse**: already locked by S1; no new provider tests.
- **live gate**: one live GLM probe for directPlan asserting GLM emits
  `test_http_endpoint` (and a `begin_case`+ws_* sequence) as multiple tool calls.
  Analyze / ToT use mock + httptest.
- **deletion regression**: existing Scout tests updated to the new tool-call
  fixtures; tests that asserted `flexibleStrings` / `relayIntent` body parsing /
  `verifyServiceAttribution` / `fallbackPlan` are removed alongside the code.
- **ToT evaluate**: deterministic-score unit tests per signal + a regression test
  that ranking still orders a known candidate set sensibly.
